# Algo View 第二阶段开发计划

记录日期：2026-10-01

状态：第二阶段已实现并完成验收（2026-10-01），M1—M6 全部完成。

第二阶段在现有冒泡排序、二分查找和通用播放器上，增加快速排序与并查集。重点是让学习者看清递归调用、树形关系和连续操作，同时保证这些状态可以准确回退和跳转。

范围来自[原始规格](algorithm-visualizer-spec.md)的用户故事 28—32。下文保留开发时的规划与验收标准；标为“建议”的算法策略、输入格式与规模限制均已在本次实现中采用，正式规则见 [README](../README.md) 与算法模块。后续如有调整，应同步更新本文、算法说明和测试。

## 阶段目标与交付范围

第二阶段完成后，学习者应能在任意一步回答：当前执行哪个函数、属于哪次调用、哪些数据刚发生变化，以及为什么发生变化。

| 交付项 | 必须具备的能力 | 完成标志 |
| --- | --- | --- |
| 快速排序 | 基准元素、分区指针、当前区间、递归调用栈及各层局部变量 | 能完整播放排序，并在回退和跳转时恢复相同调用上下文 |
| 并查集 | 父节点数组、森林、查找路径、根节点、合并及查询操作序列 | 两种视图始终一致，每次操作都有明确结果 |
| 路径压缩演示 | 展示查询时发生的每次父节点更新 | 能比较压缩前后结构，并逐步回退恢复原来的路径 |
| 共用展示与回放 | 多函数代码定位、调用上下文、操作进度、结构化结果 | 四个算法复用同一个播放器，既有功能不退化 |

继续采用 React、TypeScript、Vite、useReducer、SVG、CSS Modules、Shiki、Vitest 和少量 Playwright 测试。没有实际需求或性能证据时，不引入新的状态管理库、动画库或图布局依赖。

## 第一阶段基础与需要扩展的地方

已有执行记录包含初始快照、语句标识、变量、数组元素、展示标记和完成结果。快照独立且深冻结；播放器只按索引选择快照，通过调度标识隔离过期回调。这些行为应直接保留。

当前接口主要服务数组算法，不能仅新增两个算法文件就完成第二阶段。需要先解决以下具体限制。

| 当前实现 | 第二阶段所需变化 |
| --- | --- |
| `AlgorithmInput` 只有 `values` 和可选 `target` | 区分数组输入与并查集的节点数、操作序列和配置，保证校验与执行参数类型匹配 |
| `InputDraft` 固定为数组文本和目标文本 | 增加并查集输入编辑方式；保留输入修改后停止旧过程的规则 |
| `Snapshot.variables` 是一份扁平变量表 | 支持调用栈和每个栈帧的局部变量，同名变量不能相互覆盖 |
| `Snapshot.items` 和 `markers` 固定为数组展示 | 增加并查集状态，以及基准、访问路径、父节点变化等标记 |
| `Trace.result` 只有排序和查找结果 | 增加并查集的逐操作结果和最终结构；中途回放不能提前展示后续结果 |
| `App.tsx` 直接渲染数组，并用 `requiresTarget` 判断部分界面 | 按输入类型和展示能力组合面板，避免把并查集塞进数组或查找专用分支 |
| `CodeLine.id` 在同一算法代码中唯一 | 多个函数采用带函数含义的稳定标识，并补充调用实例上下文 |

实现方向是少量有明确类型区分的输入、状态和展示能力。不要用任意字段集合替代类型约束，也不需要建设通用插件系统。

## 快速排序

### 建议的算法规则

建议采用右端点为基准的 Lomuto 分区，处理闭区间 `[low, high]`，先递归左区间，再递归右区间。选择固定基准是为了让同一输入的轨迹稳定、便于核对；本阶段不加入随机基准、三数取中或算法版本切换。

| 项目 | 建议规则 |
| --- | --- |
| 输入 | 沿用最多 24 项、整数范围 −999 至 999；允许空数组与重复值 |
| 数据修改 | 先复制输入，保留元素稳定身份，在副本上排序 |
| 分区 | `pivot = a[high]`，`i = low`；`j` 从 `low` 扫描到 `high - 1` |
| 比较与交换 | 当 `a[j] < pivot` 时交换 `a[i]` 和 `a[j]`，再递增 `i`；扫描结束后将基准交换到 `i` |
| 自交换 | 若两个下标相同，仍记录实际执行的交换语句，说明位置未变化，不伪造移动动画 |
| 递归终止 | `low >= high` 时直接返回，并解释空区间或单元素区间无需分区 |
| 重复值 | 正确保留重复元素；不承诺相等元素的稳定排序 |
| 结果 | 返回升序数组；整个调用过程结束才标记全局完成 |

展示代码应明确分开比较、交换、指针更新和递归调用。若采用独立的 `partition` 辅助函数，代码区应同时包含它和快速排序主函数。

### 学习者看到的内容

数组视图继续显示值和索引，新增当前处理区间、基准标签、`i` 与 `j` 指针。基准值、元素身份和当前位置分别保存，基准移动后标签仍指向正确元素。当前区间之外的元素淡化，但不能因此被误标为已排序。

分区结束时，标记已经确定最终位置的基准元素；单元素区间可以标记完成。尚未处理的区间保持待处理状态。

新增调用栈面板，显示函数名、调用深度、区间参数和该层已定义的局部变量。当前调用与等待子调用返回的父调用应有清楚区别。回退到上一层调用时，数组、区间、局部变量和代码定位必须一起恢复。

建议至少提供普通、重复值、已经有序三类示例，让学习者观察分区和递归深度的差异。示例属于本地内置数据，不增加随机生成要求。

### 调用与代码定位的语义

普通语句继续采用“高亮刚执行完成的语句，展示执行后状态”。函数调用涉及进入和返回，不能在刚进入子函数时，把尚未结束的整个调用表达式描述为已完成。

建议为调用进入、函数返回提供明确的流程事件与文案：进入时标记调用位置并说明“进入函数”；子函数运行时定位其语句；返回时说明返回值和恢复的调用方。调用表达式中的赋值只有在返回值实际赋给调用方变量后才显示为完成。

每个栈帧使用确定性的独立标识。记录要区分“刚执行语句所属的调用”和“本步之后仍在栈中的活动调用”：返回步骤可能已经弹出子帧，但仍需说明刚执行的是哪个函数的返回语句。不得为了显示返回步骤而把已退出的局部变量留在当前调用中。

这些上下文直接写入快照，展示层不得通过重新执行算法或扫描历史记录来猜测调用栈。

## 并查集

### 建议的输入与操作规则

并查集输入由节点数、操作序列和路径压缩开关组成。建议节点编号固定为 `0` 至 `n - 1`，初始时每个节点单独成集，`parent[x] = x`。

| 项目 | 建议规则 |
| --- | --- |
| 输入规模 | 0—16 个节点，最多 32 条操作；属于教学规模的初始限制，需在开发时用代表性轨迹复核 |
| 操作格式 | 每行一条 `union a b` 或 `find x`，忽略空行；暂不增加脚本语法 |
| 校验 | 节点数必须为整数；节点引用必须在有效范围内；未知命令、参数个数错误和越界都提示具体行号 |
| 空输入 | 无操作时正常呈现初始结构并结束；0 个节点只接受空操作序列 |
| 合并策略 | 按集合大小合并，小树根连接到大树根；大小相等时选择编号较小的根作为新根 |
| 同集合合并 | 返回“已在同一集合”，不重复修改根节点大小或集合数量；查找阶段若开启压缩，仍可能产生父节点更新 |
| 查询结果 | `find x` 返回当前根节点；不假定根一定是集合内编号最小的节点 |
| 路径压缩 | 建议默认关闭，提供显式开关；启用后对 `find` 及 `union` 内部的查找统一生效 |

编辑操作序列、修改节点数或切换路径压缩配置，都结束旧演示并进入待生成状态。点击“生成演示”后，从独立的初始集合开始执行整个序列，不复用上一次演示的终态。

### 操作序列与状态展示

页面同时提供父节点数组和森林视图。父节点数组按节点编号排列，单元格 `parent[x]` 显示节点 `x` 的父节点；森林边与该数组逐项对应。根节点以标签标明，自己的父节点等于自身，但不绘制自环。

森林可以有多个根，布局应稳定且可重复。建议根按编号排列、子节点按编号排列；节点身份始终使用节点编号，不能把当前位置当作身份。连接方向由节点指向父节点，并在图例中说明。

操作列表显示当前操作、已完成操作及各自结果；步骤进度和操作进度分开显示。一次 `union` 中的查找、比较根、连接父节点和更新大小都属于该操作，不能在每条操作结束时让整个播放器提前停止。只有完整序列结束才产生全局 `complete`。

查询显示访问路径与找到的根。合并显示两个根、大小比较、父节点变化和集合数量变化。`size` 仅在根节点处表示有效集合大小，非根节点不展示成仍然有效的独立集合大小。

父节点、`size` 和集合数量如果由多行语句依次修改，就分别记录真实的中间状态，不提前完成后续赋值。父连接已经变化而大小或计数尚未更新时，步骤说明应指出接下来需要更新的字段；大小和计数的完整一致性在合并操作完成时验收。

### 路径压缩

建议采用迭代查找：先沿父节点找到根，再逐个将查询路径上的非根节点直接连接到根。展示代码按实际实现拆分访问、判断和赋值步骤，不能只在查询结束时替换整棵树。

每次 `parent[x]` 赋值都记录对应语句、更新前后的父节点及执行后的完整状态。赋值未改变父节点时，明确说明“已直接连接根节点”，避免制造不存在的结构变化。压缩不改变集合成员、集合数量或根节点的集合大小。

建议将下面的序列作为压缩示例，节点数设为 8，先关闭压缩运行，再开启压缩重新生成：

```text
union 0 1
union 2 3
union 0 2
union 4 5
union 6 7
union 4 6
union 0 4
find 7
find 7
```

按上述合并规则，第一次 `find 7` 前存在 `7 → 6 → 4 → 0` 的路径。启用压缩后可以逐步观察 `parent[7]`、`parent[6]` 指向根 0；第二次查询则能直接到达根。回退到任一修改前，应恢复当时的原始父节点关系。

## 共享执行记录与页面扩展

### 数据契约

建议先整理 [共享类型](../src/engine/types.ts)，再实现算法。保持 `Trace` 的有序快照和明确结束结果，新增内容按实际用途组织。

| 信息 | 需要表达的内容 |
| --- | --- |
| 输入与配置 | 明确区分数组和并查集输入；配置属于本轮轨迹，回放期间不能偷偷变化 |
| 数据状态 | 数组保留值与身份；并查集保存 `parent`、根节点有效 `size` 和集合数量 |
| 展示标记 | 比较对象、指针、基准、当前区间、访问路径、刚修改的父节点；与真实数据状态分开 |
| 调用上下文 | 函数标识、调用实例标识、参数、局部变量、活动帧、调用进入和返回信息 |
| 操作上下文 | 当前操作序号与参数、执行状态、截至当前步骤已产生的操作结果 |
| 代码位置 | 稳定语句标识，必要的函数信息，以及刚执行动作的调用实例；实际行号由代码层解析 |
| 全局结果 | 排序、查找、并查集操作序列分别使用明确结果类型，不把结构化数据塞入说明文本 |

同一算法的多个函数可先放在同一份只读代码中，语句标识采用函数前缀，例如 `quickSort.callLeft`、`partition.compare`、`find.compress`。递归时同一语句会重复出现，通过调用实例区分执行上下文，不按递归深度复制代码。

独立深冻结的快照、输入不被修改、确定性执行及语句映射校验继续生效。新增栈帧、操作结果和树状态也必须纳入冻结与历史稳定性测试。

### 展示组件

建议保留并扩展 `ArrayView`，新增调用栈、森林、并查集输入及操作列表组件。父节点数组宜使用“节点编号与父节点值”的单元格表达，不直接套用排序柱状图。

`App.tsx` 负责选择算法、输入草稿和面板组合，算法模块继续集中维护说明、规则、示例、代码与执行能力。不同输入类型可以对应少量固定编辑器；不同状态类型选择对应视图，通用代码区、步骤说明和播放控制继续复用。

新增步骤类型时，同步补齐步骤名称、图例和读屏文案。比如“连接父节点”“压缩路径”不能继续被描述成“比较元素”。小屏幕使用上下布局，数组或森林超宽时在各自区域内滚动，保证控件可操作。

### 播放与规模限制

播放器继续只负责快照索引、播放状态、速度与调度失效，不判断算法名称、递归深度或操作种类。暂停、回退、跳转、重置、重新生成及切换算法沿用第一阶段的一致性规则。

默认 5000 步上限先保持不变，同时覆盖初始化、调用事件、每条操作和最终完成状态。必须在生成过程中检查上限；超限时整体报错，不把不完整轨迹交给播放器。

开发时检查快速排序的有序、逆序和全相等最大输入，以及并查集的最长允许操作序列。如果代表性输入触及上限或产生明显卡顿，再调整可见限制并记录依据；本阶段不预先引入分批执行或后台计算。

## 测试与验收

### 快速排序

- 覆盖普通、有序、逆序、重复值、全相等、负数、空数组、单元素和最大允许规模；结果有序且元素身份集合不变。
- 每次分区完成时，基准左侧值小于基准、右侧值大于或等于基准；基准记录与实际元素身份一致。
- 条件判断、实际交换、自交换和指针更新对应正确的展示语句，不锁定无必要的固定步骤总数。
- 父子调用关系与调用顺序正确，局部变量不会跨帧混用；覆盖空区间返回、深层返回及调用方接收返回值。
- 同一步通过顺序前进、回退后前进和直接跳转到达时，数组、代码位置、标记、调用栈与变量完全一致。

### 并查集

- 覆盖多个独立集合、普通合并、同集合合并、自合并、连续查询、空序列、0 个节点及非法操作。
- 用独立的集合成员关系模型核对操作结果；根选择符合已记录的确定性策略，不能只比较展示文本。
- 任意快照的父节点均在有效范围内，非根连接无环；森林与 `parent` 数组一致。每条操作完成后，根数量等于集合数量。
- 合并仅在连接不同集合时使集合数量减少 1；每条操作完成后，根大小反映真实成员数量。中间步骤的大小和计数按刚执行的语句核对，不要求尚未执行的更新已经生效。
- 压缩开关不改变相同操作序列的集合关系；关闭时查询不改变父节点，开启时完整记录每次父节点赋值。
- 回退可以逐次恢复压缩前结构；跨操作跳转恢复对应操作指示与已完成结果，不泄露未来结果。

### 通用回归与浏览器流程

在既有测试基础上，优先补充四类跨模块流程：快速排序跨调用层回放、并查集跨操作回放、查询压缩后回退、播放中切换算法或修改输入。浏览器断言检查代码、变量、图形和解释的关联，不绑定私有组件结构。

必须继续验证首尾边界、结束自动停止、调速不改变轨迹、过期回调隔离、输入不变、快照冻结，以及多函数语句标识重复或失效时能报错。

阶段交付前运行：

```sh
npm test
npm run test:e2e
npm run build
```

同时人工核对长代码定位、最大教学规模、手机区域滚动、键盘焦点、图例和读屏动作说明。动画只能表现状态，关闭动画后仍应完整表达算法过程。

## 本阶段不包含的内容

- 用户代码编辑、编译、解释器或执行沙箱。
- 其他排序、树、图算法，以及快速排序多种分区策略对比。
- 并查集动态增删节点、删除连接或专门的可回滚并查集算法；播放器的历史快照回退已经覆盖教学回放需求。
- 一次执行整轮、整次递归或整条操作的专门按钮。
- 多算法并排性能比较、大规模数据、复杂图布局或通用插件平台。
- 账户、云端保存、跨设备同步及后端服务。
- 线上部署、域名和自动发布；可独立规划，不作为本阶段算法验收的前置条件。

## 完成标准

第二阶段只有在快速排序和并查集都具备可编辑输入、完整执行、准确解释、任意步骤回放以及明确结束结果时才算完成。调用栈、父节点数组、森林和操作列表必须使用同一份当前快照；第一阶段的两个算法仍可正常使用。

实现中采纳的算法策略、输入限制和调用步骤语义应最终写入各算法说明与 README。本文中的建议如被替换，也应一并更新，保证下一阶段接手时有唯一、可核对的规则。
