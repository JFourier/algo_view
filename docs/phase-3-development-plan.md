# Algo View 第三阶段开发计划

记录日期：2026-10-02

状态：第三阶段五项算法已实现并完成验收（2026-10-02）；范围来自 [后续算法开发路线](algorithm-roadmap.md)。

## 范围与算法规则

本阶段实现插入排序、线性查找、链表反转、递归斐波那契和 DP 斐波那契。沿用统一不可变快照、语句映射和播放器，不增加运行依赖。

| 算法 | 固定规则 | 新增展示 |
| --- | --- | --- |
| 插入排序 | 复制输入；从下标 1 开始保存 key，仅将严格大于 key 的元素右移，最后写回 key；相等值保持原始顺序 | 暂存元素、实际数组写入位置和已排序前缀；前缀有序不代表已到最终位置 |
| 线性查找 | 接受无序数组；从左到右比较，返回第一个匹配下标；失败返回 −1 | 当前扫描指针、剩余候选区间、找到结果 |
| 链表反转 | 按输入顺序构建无环单链表；迭代保存 next、修改 current.next、推进 prev/current，最终返回新头 | 固定节点身份、next 连接、null 和三个指针；每次改边独立记录 |
| 递归斐波那契 | F(0)=0、F(1)=1；先计算 F(n−1)，再计算 F(n−2)，不记忆化 | 独立调用栈、返回与赋值、子问题累计调用次数 |
| DP 斐波那契 | 同一递推定义；从边界向 n 顺序填表 | 未计算单元格、读取依赖、当前写入和最终值 |

数组和链表最多 24 项，元素与查找目标均为 −999 到 999 的整数，空序列合法。链表输入与数组一样使用逗号或空格分隔，重复值用不同节点身份区分。

两种斐波那契共享整数输入 n，范围 0—10，便于相同输入对照并限制递归轨迹规模。所有算法仍受 5000 个快照上限约束；执行接口也验证输入，不能绕过表单限制。

## 开发与验收

1. 扩展有明确类型的整数、链表输入与专用状态，接入数组暂存、链表视图和 DP 表。
2. 验证稳定排序、首次查找、逐次连接修改、递归调用/返回及 DP 依赖；所有合法 n 的两种结果一致。
3. 验证边界与规模限制、不可变与确定性、语句映射、回退/跳转与旧任务隔离。
4. 运行单元测试、TypeScript/生产构建、桌面和手机浏览器验收，更新 README 和路线状态。

方法标签、完整调用树及第三阶段之外的候选算法仍留待后续。

## 实现与验收记录

- 五项算法已通过统一注册入口接入原播放器；新增链表和整数输入，以及暂存元素、固定节点链表、递归调用次数和 DP 状态表。播放器及调度逻辑无需新增算法分支。
- 插入排序快照记录实际数组槽位内容，包括右移时的临时副本；暂存区持续保留 key，最终验证相同值的身份顺序稳定。前缀有序与最终就位分开显示。
- 链表逐次记录连接赋值及指针变化，单独执行 `head = prev` 后返回新头；每个快照保留全部节点，不因旧头断开而丢失节点。24 节点产生 126 个快照。
- 两版斐波那契在所有合法 n 上结果一致。n=10 时 F(10)=55，递归版 177 次调用、710 个快照；DP 版 53 个快照。初始 DP 表尚未分配，分配后未计算项为 null，每次依赖读取和状态写入均可回退。
- 手机导航限制在独立滚动区域，避免九个算法的展开菜单挤出播放控件；长链表与 DP 表仅在各自区域横向滚动，长变量值可换行。
