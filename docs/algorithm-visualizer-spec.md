# 算法演示网页规格书

记录日期：2026-10-01

文档用途：固定本次需求分析与技术选型结论，作为后续开发和验收的基线。

当前阶段：第一阶段已实现冒泡排序、二分查找和通用执行回放；具体规则、启动方式与验证命令见 [README](../README.md)。本规格继续作为需求与验收基线。

本规格覆盖第一版的完整学习与回放体验，并记录快速排序、并查集等后续算法的扩展要求。标注为“后续扩展”的内容不属于第一版交付；尚未确定的细节集中列于 Further Notes，不视为已确认需求。

## Problem Statement

算法学习者阅读代码时，需要在循环、条件判断、变量变化和数据结构变化之间建立联系。仅查看最终结果，无法理解中间过程；仅观看动画，也难以判断当前画面与哪条语句对应。

本项目需要提供一个算法演示网页，让学习者在任意一步都能回答：

1. 刚执行的是哪条语句？
2. 当前变量和数据结构是什么状态？
3. 本次执行做出了什么判断，或者造成了什么变化？

项目还需要持续增加算法内容。新增排序、查找、树或图相关算法时，已有的代码展示、播放控制和回放能力应能够复用，算法特有的逻辑应集中维护。

## Solution

构建一个带代码映射的算法执行播放器。用户选择内置算法，使用示例数据或修改输入，再按实际执行顺序逐步查看代码、变量和数据结构的变化。

第一版允许修改输入数据，算法代码只读。首先完成冒泡排序的完整体验，再接入二分查找，验证统一执行与回放机制。后续接入快速排序和并查集，分别扩展递归调用栈、树形展示及连续操作序列。

主要交互流程为：选择算法 → 设置输入 → 生成执行记录 → 单步查看或自动播放 → 回退或跳转核对 → 修改输入重新演示。

页面包含以下内容：

- 代码区：展示完整内置代码，并高亮刚执行完成的语句。
- 数据区：展示数组或其他数据结构，以及比较对象、指针和范围等视觉标记。
- 执行信息区：展示当前变量、判断结果和步骤说明。
- 播放控制区：提供上一步、下一步、播放、暂停、速度调节、重置和进度跳转。
- 算法与输入区：选择算法、使用示例、修改输入，并呈现输入校验结果。

各区域由同一份执行记录和当前步骤驱动。点击“下一步”后，高亮刚执行完成的语句，并展示该语句执行后的状态。

核心验收标准：任意一步暂停后，学习者能够通过页面指出刚执行的语句、读出当前变量与数据，并理解本步的判断或变化；回退再前进时，这些信息保持一致。

## User Stories

以下 1—27 项覆盖第一版学习体验与开发要求，28—32 项描述后续扩展目标。

1. 作为算法学习者，我希望选择不同的内置算法，以便观察不同问题的求解过程。
2. 作为算法学习者，我希望看到算法的简要说明，以便了解它解决的问题及输入要求。
3. 作为算法学习者，我希望直接使用示例数据，以便快速开始演示。
4. 作为算法学习者，我希望修改输入数据，以便观察不同输入对执行过程的影响。
5. 作为算法学习者，我希望在输入不符合要求时得到明确提示，以便修正输入后继续学习。
6. 作为算法学习者，我希望查看完整、只读的算法代码，以便在演示过程中保留代码上下文。
7. 作为算法学习者，我希望执行位置与代码高亮同步，以便把每次变化对应到具体语句。
8. 作为算法学习者，我希望一次前进一步，以便按自己的节奏理解算法。
9. 作为算法学习者，我希望回到上一步，以便核对变化前后的状态。
10. 作为算法学习者，我希望自动播放执行过程，以便观察算法的整体推进方式。
11. 作为算法学习者，我希望暂停自动播放，以便仔细检查当前步骤。
12. 作为算法学习者，我希望调节播放速度，以便兼顾初学时的理解和复习时的效率。
13. 作为算法学习者，我希望查看当前进度并跳转到指定步骤，以便重复观察感兴趣的执行片段。
14. 作为算法学习者，我希望重置演示，以便从同一输入的初始状态重新开始。
15. 作为算法学习者，我希望看到当前变量值和指针位置，以便理解循环和分支如何推进。
16. 作为算法学习者，我希望看到每一步的简短解释，以便理解比较、交换和范围更新的原因。
17. 作为算法学习者，我希望即使数据没有变化，也能看到本步的比较或判断结果，以便理解控制流程。
18. 作为算法学习者，我希望通过标签和图例理解视觉标记，以便分清比较对象、当前范围和已完成区域。
19. 作为算法学习者，我希望在冒泡排序中分别观察比较与交换，以便理解判断和修改数据的区别。
20. 作为算法学习者，我希望在冒泡排序中看到每轮结束后已经确定的位置，以便理解算法逐轮推进的规律。
21. 作为算法学习者，我希望设置二分查找的目标值并看到边界和中点，以便理解候选范围如何缩小。
22. 作为算法学习者，我希望明确知道二分查找是否找到目标，以便理解成功与失败的终止条件。
23. 作为算法学习者，我希望重复值、空输入和单元素输入有清楚的处理结果，以便观察算法的边界行为。
24. 作为算法学习者，我希望修改输入或切换算法后开始独立的新一轮演示，以便避免旧过程与新过程混淆。
25. 作为算法学习者，我希望调整播放速度或来回跳转时执行结果保持一致，以便信任页面展示的算法过程。
26. 作为算法维护者，我希望集中维护每个算法的说明、代码、输入规则和执行逻辑，以便新增或修改算法时减少遗漏。
27. 作为算法维护者，我希望新算法复用已有播放控制和适用的数据展示能力，以便持续扩展内容。
28. 作为算法学习者，我希望在快速排序中看到基准值、分区指针和当前区间，以便理解分区过程。
29. 作为算法学习者，我希望看到快速排序的递归调用栈和每层变量，以便理解同一段代码在不同调用中的含义。
30. 作为算法学习者，我希望在并查集中同时查看父节点数组和树形结构，以便对应内部存储与集合关系。
31. 作为算法学习者，我希望按顺序设置并播放并查集的合并和查找操作，以便观察集合关系随操作变化。
32. 作为算法学习者，我希望在启用路径压缩时看到查询如何修改父节点关系，以便理解查询也可能改变数据结构。

## Implementation Decisions

### 交付范围与开发顺序

1. 第一版采用内置算法代码，只允许修改输入，不提供手动编辑和执行用户代码的能力。
2. 先完成冒泡排序从输入到结束的完整流程，再接入二分查找，验证数组不变但指针、判断及范围发生变化的执行过程。
3. 快速排序和并查集为下一阶段扩展内容。第一版需要保留合适的扩展接口，但不要求提前实现所有展示形式。
4. 单步的底层单位是可解释的执行步骤，并映射到展示语句。同一行可以执行多次，条件判断可以产生不修改数据的步骤。
5. 内置展示代码尽量保持一行一个关键动作。具体展示语言尚未确定，不将 TypeScript 的实现语言等同于用户看到的代码语言。

### 技术基线

| 领域 | 选择 | 决策理由 |
| --- | --- | --- |
| 页面开发 | React + TypeScript | 组织交互与展示，并约束算法输入、执行状态和步骤之间的关系。 |
| 开发与构建 | Vite | 提供开发环境和静态构建能力。 |
| 播放状态 | React useReducer | 集中管理播放动作及状态变化，便于通过行为验证一致性。 |
| 数据可视化 | React 绘制 SVG | 精确控制数组元素、指针、节点、标签与连线，并复用基础绘制能力。 |
| 样式 | CSS Modules + CSS 变量 | 管理局部样式和统一视觉配置。 |
| 基础动画 | CSS 过渡 | 表现位置和颜色变化；复杂路径或协调动画出现实际需求时再评估 Motion。 |
| 代码语法高亮 | Shiki | 展示只读算法代码，并为执行位置建立行级标记。 |
| 逻辑测试 | Vitest | 验证算法结果、执行记录及播放器状态行为。 |
| 浏览器流程测试 | 少量 Playwright 测试 | 验证页面交互和播放过程中发生操作切换的行为。 |
| 运行与部署 | 浏览器执行，静态托管 | 当前功能不依赖服务端计算、账户或云端数据。 |

上述选型构成当前开发基线。Motion 为条件性备选，不属于首版必须引入的依赖；Zustand 等额外状态库在出现明确需求后再评估。具体依赖版本在初始化时核对兼容性并锁定，不在本规格中写死。

### 算法模块与扩展接口

1. 每个算法作为独立模块，集中提供标识、说明、展示代码、输入规则、示例以及执行记录生成能力。
2. 通过统一注册入口接入算法。新增使用既有数据结构的算法时，主要工作应集中在算法模块及注册，不应逐个修改播放器和代码高亮逻辑。
3. 算法执行逻辑使用独立 TypeScript 模块，不依赖 React、DOM、播放定时器或动画库。
4. 执行接口接收已校验输入，产生按实际执行顺序排列的记录及明确的结束结果。相同输入及相同算法配置应得到一致的执行过程。
5. 统一执行记录的公共信息，包括执行位置、变量、数据状态、步骤解释和展示标记；算法特有的状态允许通过类型扩展表达。
6. 数组、树等不同数据结构使用适合自身的展示模块。排序与二分查找复用数组展示能力，算法分别提供比较、基准值或候选范围等信息。
7. 引入新数据结构时可以增加相应展示模块；已有播放控制应继续复用。第一版根据冒泡和二分的真实差异建立接口，避免为尚未出现的情况设计大量抽象。

### 执行记录与代码关联

1. 执行记录在真实算法运行时生成，包含比较、判断、变量更新和数据修改等对理解流程有意义的步骤。
2. 展示语句通过稳定标识与执行记录关联，实际行位置由代码展示层解析或映射。调整代码排版后应保持关联正确。
3. 第一步执行前展示初始状态，不将尚未执行的语句标记为已执行。步进后统一展示刚执行完成的语句及执行后的状态。
4. 算法状态与视觉标记区分维护。例如数组值、索引变量属于算法状态，比较强调和已完成区域属于解释性的展示信息。
5. 首版保存每一步的独立、不可变状态快照，用于回退和进度定位。后续步骤不能修改已经记录的历史状态。
6. 对输入规模和总执行步数设置上限，避免无上限地生成完整轨迹。具体数值根据代表性算法与浏览器表现确定，超过限制时向用户给出明确提示。
7. 语法高亮在展示代码加载或变化时计算。正常步进只更新当前执行语句的标记，避免每一步重新计算整段代码的语法高亮。

### 播放与交互一致性

1. 播放状态集中管理当前轨迹、步骤索引、播放状态和速度等设置。代码区、变量区、说明区和数据区使用相同的步骤作为依据。
2. 上一步恢复对应快照，包括变量、数据结构、说明和视觉标记；后续递归算法也应恢复相应调用上下文。
3. 进度跳转直接定位目标步骤，不要求把跳过的所有步骤依次播放。
4. 重置回到当前输入的初始状态；修改输入或切换算法则结束旧过程，并基于新的输入和算法建立新过程。
5. 动画只表现状态之间的过渡，不负责决定算法计算结果或修改执行记录。播放速度不改变语句执行顺序和结果。
6. 回退、跳转、重置、切换算法及重新运行时，应妥善停止或失效化旧的调度和过渡任务，防止过期任务再次推进当前演示。
7. 暂停后不再自动进入后续步骤。当前视觉过渡如何收尾属于待落实的交互细节，但不能造成代码、变量与最终停留状态不一致。
8. 数据元素需要稳定身份，数组位置与元素身份应区分，保证重复数值仍能被正确跟踪和展示。
9. 颜色含义通过图例和标签说明，比较、指针及范围等关键信息不能只依赖颜色表达。

### 算法特定行为

| 算法 | 必须表达的内容 | 需要在对应算法实现时固定的规则 |
| --- | --- | --- |
| 冒泡排序 | 相邻比较、条件结果、交换、循环变量、每轮完成区域。 | 展示代码采用的具体循环与终止形式，步骤必须与之对应。 |
| 二分查找 | 目标值、左右边界、中点、候选区间、找到或未找到的结果。 | 区间开闭规则、重复目标值的返回语义，以及无序输入的处理方式。 |
| 快速排序（后续扩展） | 当前处理区间、基准值、分区指针、进入和退出递归、调用栈。 | 基准选择与分区实现，代码、步骤与动画保持一致。 |
| 并查集（后续扩展） | 父节点数组、森林结构、查找路径、根节点，以及连续操作的结果。 | 合并策略、是否启用路径压缩、操作序列格式。 |

二分查找必须明确说明有序输入要求。遇到无序输入时提示用户，或通过明确可见的操作进行排序，不可静默修改用户输入。

并查集的树形结构可能包含多个根；若后续启用路径压缩，查找产生的父节点修改也必须进入执行记录。

## Testing Decisions

### 测试接口与原则

项目当前没有实现代码、已有测试、领域词汇表或相关 ADR，因此没有现成的测试先例可以沿用。本规格沿用前述“独立执行引擎 + 通用播放器”的设计，以公开行为作为测试依据。

主要测试 seam 放在“输入算法及数据，产生可回放执行记录，并响应播放动作”的高层接口。允许算法与播放器内部拆分实现，但测试不应依赖私有辅助函数或内部存储方式。再使用少量浏览器流程测试验证这个接口与页面的连接。

好的测试需要验证学习者或调用者可观察的结果及不变量，不应只是重复实现中的分支。测试重点包括正确结果、步骤含义、历史状态稳定性、回放一致性和过期任务隔离；不将内部函数调用次数、某个 CSS 类名或无必要的固定步骤总数作为正确性依据。

### 执行与回放行为

1. 冒泡排序对代表性输入得到正确结果，并保留元素数量和内容；覆盖已经有序、逆序、重复值、空数组和单元素等情况。
2. 比较步骤即使不修改数组，也包含正确的执行位置、比较对象、判断结果和说明；交换步骤反映实际的数据变化。
3. 二分查找对目标存在、不存在、位于边界、空数组、单元素和重复值等情况符合所选实现的公开语义；搜索范围与代码规则一致。
4. 任意历史快照在后续执行后保持不变；调用者提供的输入不会因生成记录而被意外修改。
5. 相同输入和算法配置产生一致的执行过程；同一目标步骤经顺序前进、回退后前进、直接跳转到达时，得到一致的代码位置、变量和数据状态。
6. 在开头、结尾执行前进、回退或继续播放时，步骤索引不会越界；执行完成后自动播放停止。
7. 修改播放速度不会改变最终结果和执行顺序；重置后恢复当前输入的初始状态。
8. 超出输入或步骤限制时返回明确结果，不生成无法正常浏览的无界轨迹。
9. 新算法通过注册及执行接口接入通用回放；使用二分查找验证播放器没有依赖冒泡排序的特有事件或状态。
10. 展示代码调整排版后，执行位置仍可映射到正确语句；映射失效能够被验证发现。

### 浏览器流程

1. 从选择算法、修改输入到单步执行，检查代码高亮、变量、说明与图形表达一致。
2. 自动播放中暂停、回退、跳转或重置，检查最终停留步骤正确，旧任务不能再次推进演示。
3. 播放过程中切换算法或修改输入重新运行，检查旧过程不会污染新过程。
4. 检查无效输入、有序输入要求、完成结果和图例是否能被用户明确理解。
5. 检查语法高亮与当前执行标记能同时正确展示，包含重复执行同一语句的情况。

### 后续扩展的验收补充

- 快速排序：分区与递归上下文正确，回退和跳转能够恢复相应调用栈及当前区间。
- 并查集：操作结果、根节点关系和父节点更新正确；启用路径压缩后，查询造成的结构变化可以前进、回退和核对。

## Out of Scope

以下内容不属于第一版交付：

- 手动编辑、编译或执行用户提交的算法代码。
- 通用解释器、代码调试器或用户代码执行沙箱。
- 多种展示语言之间的自动转换或同步执行。
- 快速排序、并查集及其他算法的正式交付；本规格保留其扩展需求。
- “执行完一轮循环”“跳到下一次交换”等更粗粒度的步进方式。
- 账户、登录、云端收藏、跨设备学习记录及相关后端。
- 大规模数据的性能比较或压力测试工具；第一版以教学规模演示为目标。
- 为假设性的扩展预先建设通用插件平台、复杂状态管理体系或全部图形布局能力。

## Further Notes

### 术语约定

| 术语 | 含义 |
| --- | --- |
| 算法模块 | 提供某个内置算法的说明、展示代码、输入规则、示例和执行能力的模块。 |
| 执行步骤 | 一次具有可解释含义的执行事件，可以改变数据，也可以只完成判断或变量更新。 |
| 执行记录／轨迹 | 按执行顺序保存的步骤及状态；“轨迹”是执行记录的简称。 |
| 状态快照 | 某一步完成后需要恢复的数据与上下文，不随之后的执行改变。 |
| 展示标记 | 比较强调、指针、候选范围、已完成区域等解释信息。 |
| 播放器 | 根据播放动作选择当前步骤，并协调代码、状态与说明展示的模块。 |
| 展示模块 | 将某种数据结构及其标记绘制为可视内容的模块。 |
| seam | 可通过公开接口替换实现或测试行为的位置。本项目优先使用执行与回放的高层接口。 |

### 尚待实现阶段明确的细节

这些细节尚未在对话中确定。实现时应采用明确规则，并同步记录到对应算法说明和测试中；它们不阻塞当前技术基线的确定。

- 面向学习者展示的代码语言。
- 冒泡排序是否包含提前终止优化，以及相应的展示代码版本。
- 二分查找采用闭区间还是半开区间；重复目标值返回任意位置、首个位置还是其他约定。
- 无序二分输入采用提示修正，还是提供显式排序操作。
- 输入规模、值域和执行步数的具体上限。
- 暂停时尚未完成的视觉过渡如何收尾。
- 后续快速排序的基准选择、分区方式，以及并查集的合并与路径压缩策略。
- 最终视觉风格、移动端布局和静态托管平台。

### 扩展性验收准则

新增使用既有数据结构的算法时，通常只需要新增算法模块并注册；新增数据结构时，再补充对应展示能力。播放控制、代码高亮和回放机制应保持可复用。

当出现实际需求或性能证据时，再评估更复杂的动画、状态管理、布局计算或分批轨迹生成。新增依赖应解决明确问题，并维持执行记录作为状态依据的约束。
