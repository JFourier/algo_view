## 当前基础

目前已完成冒泡排序、快速排序、二分查找、并查集，以及本路线第三阶段的插入排序、线性查找、链表反转、递归斐波那契和 DP 斐波那契。具体规则与验收记录见 [README](../README.md)、[第二阶段开发计划](phase-2-development-plan.md)和[第三阶段开发计划](phase-3-development-plan.md)。

现有页面具备数组及暂存元素、指针、区间、调用栈、并查集父节点表与森林、链表连接、递归调用次数和一维 DP 表，以及统一的代码定位和快照回放能力。导航已按算法的 `category` 自动生成两级菜单。

并查集森林、链表和一维 DP 表已有专用展示组件。后续通用树、图和二维动态规划状态表仍需增加对应的数据状态、输入与视图。

## 第三阶段建议范围

以下保留第三阶段原建议范围；这 5 项现已具备完整输入、逐步解释、回退跳转和明确结果。

| 算法 | 学习目标 | 可复用能力与需要补充的展示 |
| --- | --- | --- |
| 插入排序 | 理解已排序区间、待插入元素和逐项移位 | 复用数组与指针展示，补充待插入元素的暂存状态及写入标记 |
| 线性查找 | 理解逐项检查，并与需要有序输入的二分查找对照 | 复用数组、目标输入、比较和找到结果的展示 |
| 链表反转 | 理解保存下一节点、修改连接和推进指针的顺序 | 新增链表节点、`next` 连接、空指针及 `prev/current/next` 标记 |
| 递归斐波那契 | 理解调用展开、返回值传递及相同子问题被反复求解 | 复用独立调用栈与返回值展示，新增整数输入；完整调用树可后续补充 |
| DP 斐波那契 | 理解保存已有结果、状态依赖及按顺序计算 | 新增一维 DP 状态表，区分未计算、正在依赖和刚完成写入的单元格 |

递归斐波那契与 DP 斐波那契采用同一问题定义和结果约定，用户可以使用相同的小规模输入分别演示，观察重复求解与状态复用的区别。递归版本会产生大量调用，需要根据轨迹规模确定较小的输入上限。

具体递推边界、查找重复值时的返回规则、链表输入格式和新增规模限制已写入对应算法说明、测试和第三阶段开发计划。现有快照不可变、输入不被修改、语句映射和过期播放任务隔离规则继续适用。

## 建议开发顺序

以下第三阶段开发顺序现已完成；后续继续按其后的展示能力扩展建议推进。

1. **补充数组算法**：实现插入排序和线性查找，复用已有数组展示，补齐暂存与移位语义。
2. **增加链表展示**：实现链表反转，使每次连接修改都能准确前进、回退和跳转。
3. **完成递归与动态规划对照**：实现两种斐波那契，补充整数输入和 DP 状态表，并验证相同输入的最终结果一致。

上述 5 项完成后，再按展示能力逐步扩展：

- 归并排序需要辅助数组和写回过程；堆排序需要数组位置与堆结构之间的对应关系。
- 树遍历需要通用树视图；层序遍历还需要队列展示，再逐步扩展二叉搜索树操作。
- 图算法需要图输入、边和访问状态，优先考虑 DFS 与 BFS，再扩展拓扑排序、Dijkstra 和 Kruskal。Kruskal 可以复用并查集的算法经验，补充排序边与生成树的展示。
- 动态规划从一维状态表逐步扩展到二维表和解的构造，覆盖零钱兑换、0/1 背包与最长公共子序列。
- 全排列与 N 皇后需要明确呈现当前选择、撤销操作和已产生的解，避免把回溯仅展示成调用栈变化。

## 分类与方法标签

建议采用“一个主分类加多个方法标签”。主分类用于导航归属，标签用于说明算法采用的方法。

| 算法 | 主分类 | 方法标签示例 |
| --- | --- | --- |
| 快速排序 | 排序 | 递归、分治 |
| 链表反转 | 链表 | 指针操作；采用迭代实现时标记迭代 |
| 递归斐波那契 | 递归与回溯 | 递归 |
| DP 斐波那契 | 动态规划 | 状态转移、迭代 |
| Kruskal | 图 | 贪心、并查集 |

同一算法保留一个主入口，避免为多个标签重复注册。递归和动态规划并不互斥，例如记忆化搜索可以同时带有这两种标签。

当前实现只有主分类与两级菜单，方法标签属于后续建议，尚未接入页面。
